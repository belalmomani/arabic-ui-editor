# قائمة النشر على Google Play — بالترتيب

## 0) قبل أي شيء
1. ارفع هذه النسخة إلى GitHub وتأكد أن وظائف CI كلها خضراء (البناء، المنطق، الواجهة، verify-export). **هذه النسخة رُقّيت إلى targetSdk 36 / AGP 8.9.3 / Gradle 8.11.1 دون ترجمة محلية — أول تشغيل CI هو الفحص الحقيقي.**
2. جرّب الـ APK على هاتفك: إنشاء مشروع، قالب، تصدير، إنشاء تلقائي.

## 1) مفتاح الرفع (مرة واحدة)
1. GitHub ← Actions ← **Create upload key** ← Run workflow ← اكتب كلمة مرور (12+ حرفًا وأرقامًا فقط).
2. نزّل artifact باسم `upload-key-secrets` واحفظ `upload.jks` و`secrets.txt` في مكان آمن خارج GitHub (نسخة احتياطية). ثم احذف الـ artifact.
3. Settings ← Secrets and variables ← Actions ← أضف 4 أسرار بالقيم من `secrets.txt`:
   `UPLOAD_KEYSTORE_BASE64`, `UPLOAD_KEYSTORE_PASSWORD`, `UPLOAD_KEY_ALIAS`, `UPLOAD_KEY_PASSWORD`.
4. لا تنشر هذه القيم لأحد (ولا تلصقها هنا).

## 2) بناء الحزمة
Actions ← **Release AAB** ← Run workflow ← نزّل `app-release.aab` من الـ artifact.
(رقم الإصدار versionCode يزيد تلقائيًا مع كل تشغيل.)

## 3) Play Console
1. حساب مطوّر (رسوم 25$ مرة واحدة + توثيق الهوية). إن كان حسابًا شخصيًا جديدًا فقد يُطلب اختبار مغلق بعدد معيّن من المختبرين لمدة محددة قبل الإنتاج — راجع الشرط الحالي داخل Console.
2. أنشئ تطبيقًا: الاسم، عربي، تطبيق، مجاني.
3. فعّل **Play App Signing** (الافتراضي) وارفع الـ AAB.
4. املأ كل ما في `STORE_LISTING.md`، وانشر سياسة الخصوصية على رابط عام.
5. أرسل للمراجعة (ابدأ باختبار داخلي ثم مغلق ثم إنتاج).

## 4) مخاطر الرفض المعروفة (وكيف عالجناها)
- **targetSdk:** مطلوب 36 → تم.
- **سياسة الخصوصية + Data safety:** جاهزة، تحتاج بريدك ورابطًا عامًا.
- **الإعلانات (0.93.0):** AdMob: بانر في شاشة المشاريع + بيني بعد التصدير/البناء الناجح فقط (لا عند الفتح ولا الإغلاق ولا أثناء التصميم)، بفاصل أدنى دقيقتان، ونافذة موافقة UMP. النسخة التجريبية تستخدم معرّفات اختبار Google، والإصدار المعرّفات الحقيقية. صرّح في Play Console: «يحتوي على إعلانات» + «معرّف الإعلان» + Data safety كما في STORE_LISTING.
- **الأذونات:** INTERNET وACCESS_NETWORK_STATE وAD_ID.
- **انتحال/علامات:** الاسم والأيقونة أصليان؛ لا تستخدم أسماء مزوّدي AI/GitHub في اسم التطبيق أو أيقونته.
- **محتوى مولَّد بالذكاء الاصطناعي:** سياسة بلاي للمحتوى المولَّد تتطلب آلية إبلاغ للتطبيقات التي تُنتج محتوى للعامة؛ تطبيقنا يولّد تصاميم/نصوصًا للمستخدم نفسه فقط ولا ينشرها. أجب بذلك في النموذج إن سُئلت.
- **الأمان:** رمز GitHub ومفتاح AI مشفّران بمفتاح Android Keystore (0.92.1).
- **التطبيقات التي تبني تطبيقات:** لا مشكلة سياسة معروفة، لكن لا تدّعِ في الوصف أن القوالب تتصل بخدمات حقيقية (Meta API، دفع…)، فهي واجهات فقط.

## 4-ب) مراجعة سياسات Google (نوفمبر 2026)
- **الكود القابل للتنفيذ (Device and Network Abuse):** المنع يخص تنزيل dex/JAR/.so من خارج Play. محرّك JavaScript (Rhino) يعمل داخل مفسّر معزول: `ClassShutter` يمنع أي وصول لـ Java وAndroid، ومهلة زمنية، و`initSafeStandardObjects`. وإجراءات المشاريع التي يولّدها الذكاء الاصطناعي تقتصر على «انتقال/رجوع» بلا سكربت. المصدر: [سياسة Device and Network Abuse](https://support.google.com/googleplay/android-developer/answer/9888379).
- **المحتوى المولَّد بالذكاء الاصطناعي:** السياسة تستهدف تطبيقات الدردشة وتوليد الصور والصوت/الفيديو لأشخاص حقيقيين؛ تطبيقنا أداة إنتاجية يستخدم فيها المستخدم مفتاحه ولا ينشر المحتوى للعامة، فهو خارج النطاق على الأرجح، والسياسة لا تذكر حالة «مفتاحك الخاص» صراحة. المصدر: [سياسة AI-Generated Content](https://support.google.com/googleplay/android-developer/answer/14094294).
- **بيانات المستخدم/الخصوصية:** إفصاح داخل التطبيق (حول التطبيق + نافذة GitHub + نافذة مفتاح AI) + سياسة خصوصية على رابط عام + Data safety.
- **اختبار الحسابات الجديدة:** الحسابات الشخصية المنشأة بعد 13 نوفمبر 2023 تحتاج اختبارًا مغلقًا بـ 12 مختبرًا على الأقل متصلين 14 يومًا متتاليًا قبل طلب الإنتاج. المصدر: [Play Console Help](https://support.google.com/googleplay/android-developer/answer/14151465).
- **targetSdk 36:** مطلوب منذ 31 أغسطس 2026. المصدر: [Android Developers](https://developer.android.com/google/play/requirements/target-sdk).

## 5) ما لا أستطيع ضمانه
لا أحد يضمن قبول Google للتطبيق؛ القرار لمراجعتها. ما فعلته هو إزالة الأسباب المعروفة للرفض. إن رُفض ستصلك رسالة بالسبب — الصقها هنا لنعالجها.
